## Story

**Como** worker (unidade 4),
**quero** chamar o motor por um contrato estável (`docredux_engine.api`),
**para que** triagem, processamento e folha de contato sejam jobs independentes do código das regras.

Rastreia: FR-5, FR-6, FR-8, FR-12, FR-13, FR-14 · Spec: §4 · Depende de: 2.2

## Acceptance Criteria

1. `triar` acerta tipo e perfil dos ex. 01–05.
2. Os três casos de recusa (escaneado, protegido, corrompido) retornam o motivo certo; `excede_paginas` (> 300) e `excede_tamanho` também; template desconhecido retorna `perfil_id = None` e `tipo = "desconhecido"`.
3. `Relatorio` serializa em JSON e tem todos os campos do spec §4.
4. Síntese só para relatório (Q4): `sintese_disponivel = False` em ficha; `processar` com `modo="sintese"` num perfil de ficha levanta `MotorErro`.
5. `processar`: despacho por `perfil["tipo"]`; gate de cobertura 99,5% no modo original (`gate="bloqueado"` + `motivo_gate`); relatório com modificações (removido/reorganizado), estrutura, regras disparadas e tempos.
6. `validar_perfil` com JSON Schema derivado de `perfis/*.json`; `[]` para os dois perfis semente.
7. Regressão 2.2 continua verde.
