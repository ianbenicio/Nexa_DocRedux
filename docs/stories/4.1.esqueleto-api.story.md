## Story

**Como** participante do piloto,
**quero** uma API que me reconheça pelo login do Supabase, mostre meu perfil e registre o aceite do termo e a troca da senha provisória,
**para que** as telas da unidade 5 tenham uma base segura e o envio só aconteça depois do termo aceito.

Rastreia: FR-1, FR-18, CON-1 · Spec: §9 (autenticação, erros, CORS), §13, DT-14, DT-19 · Depende de: 3.1–3.3

## Acceptance Criteria

1. Sem `Authorization: Bearer` ou com JWT inválido/expirado → 401 `nao_autenticado`, no formato `{"erro": {"codigo", "mensagem"}}` do §9.
2. Usuário comum em rota `/admin/*` → 403 `proibido`; o papel é lido do banco a cada requisição.
3. Termo não aceito (ou versão antiga) → 403 `termo_pendente` nas rotas de envio (`POST /documentos`, `/orcamento`, `/confirmar`).
4. `POST /me/termo {versao}` grava `termo_versao` e `termo_aceito_em`; versão diferente da atual (`config.termo_versao_atual`) → 422 `validacao`.
5. `POST /me/senha-trocada` zera `senha_provisoria`; `GET /me` devolve o valor, o saldo e se o termo foi aceito.
6. Conta com `exclusao_conta_em` preenchido → 401 mesmo com JWT ainda válido (o ban do Auth não invalida tokens já emitidos).
7. `GET /health` responde sem autenticação: DB ok, algum worker com `visto_em` < 60 s, versão.
8. CORS só para a origem do `web/` (`WEB_ORIGIN`). Nenhum log grava conteúdo de documento.
9. A API conecta ao Postgres como `docredux_backend`, sem prepared statements (modo transação do pooler, DT-14), pool ≤ 5; a mesma app roda com uvicorn e como função Python da Vercel.

## Dev Notes

- O `sub` do JWT é o `usuario_id` (= `perfis_usuario.id`). Papel e exclusão vêm do banco, não do token.
- Supabase local (CLI 3.2): conferir se o JWT é HS256 (segredo) ou ES256 (JWKS em `/auth/v1/.well-known/jwks.json`); suportar os dois.
- Senha do `docredux_backend`: definida localmente por script de dev (nunca versionada); a definitiva é da unidade 7.
